# Proxy Tunnel

Приложение в строке меню macOS: держит SSH-туннель к своему зарубежному серверу и пускает через него только
выбранные домены (по умолчанию Claude, Anthropic и Threads). Остальной трафик, включая российские сервисы и
банки, идёт напрямую. VPN не нужен и не мешает: в режиме «VPN» приложение просто снимает свои настройки.

## Как устроено

```
Мак                                              сервер (Ubuntu/Debian)
Claude Code ── HTTPS_PROXY ─┐
браузер, Claude.app ── PAC ─┤
                            └─ 127.0.0.1:8888 ══ ssh -L ══ tinyproxy 127.0.0.1:8888 ── интернет
```

- **Сервер универсальный**: на нём только tinyproxy, слушающий `127.0.0.1`, и пользователь `tunnel`, которому
  разрешено одно — проброс на этот порт (`restrict,port-forwarding,permitopen=…` в `authorized_keys`,
  `ForceCommand nologin`). О Claude сервер ничего не знает. Скрипт установки — `server/setup.sh`.
- **На Маке** приложение запускает `/usr/bin/ssh -N -L` дочерним процессом и переподключает его с паузой
  (`Tunnel.swift`), раздаёт PAC-файл из памяти на `127.0.0.1:8889` (`PacServer`) и в режиме «Туннель»
  включает этот PAC для сетевой службы и пишет `env.HTTPS_PROXY`/`NO_PROXY` в `~/.claude/settings.json`
  (`Model.swift`, `ClaudeSettings`). Другие ключи этого файла не трогаются, перед записью делается `.bak`.
- PAC без запасного `DIRECT`: нет туннеля — эти домены не открываются вовсе, а не уходят с российского адреса.
- Проверка (кнопка «Проверить», фоном каждые 2 минуты): ssh жив, порт отвечает, `claude.ai/cdn-cgi/trace`
  через туннель видит адрес сервера и не RU, PAC включён и раздаётся, прокси прописан в Claude Code.

## Что где лежит на Маке

Не в репо — у каждого пользователя своё:

- `~/Library/Application Support/Proxy Tunnel/config.json` — сервер, порты, интерфейс, сетевая служба, домены;
- `~/Library/Application Support/Proxy Tunnel/id_ed25519` — ключ туннеля (создаётся кнопкой «Создать ключ»);
- `…/known_hosts` — ключ сервера, запоминается при первом подключении;
- `~/Library/Logs/Proxy Tunnel.log` — журнал ssh.

## Установка

macOS 13 и новее, Intel и Apple Silicon.

1. Скачать `ProxyTunnel-<версия>.dmg` со страницы Releases, открыть, перетащить «Proxy Tunnel» в «Программы».
2. Первый запуск: приложение не нотаризовано Apple, поэтому двойной щелчок его не откроет.
   macOS 13–14: правый щелчок по приложению → «Открыть» → «Открыть». macOS 15 и новее: попытаться открыть,
   затем «Системные настройки» → «Конфиденциальность и безопасность» → «Всё равно открыть».
3. Окно настроек откроется само — дальше «Настройка сервера».

Образ собирает `menubar/package.sh` → `dist/` (не в git).

## Сборка из исходников

```bash
menubar/build.sh                       # swiftc, Intel + Apple Silicon, подпись ad hoc → menubar/build/Proxy Tunnel.app
open "menubar/build/Proxy Tunnel.app"  # или скопировать в /Applications
```

Нужны Command Line Tools (`swiftc`), macOS 13+. Xcode-проекта нет. Тестов нет: проверка — сборка и
`bash -n` скриптов.

## Настройка сервера

Сервер — любой зарубежный Ubuntu или Debian с доступом по ssh; пока он не задан, приложение показывает ссылку
«Арендовать сервер» (`Config.rentServerURL`, реферальная ссылка на cloud4box). На сервер ставится только то,
что в `server/`: `setup.sh` (tinyproxy и пользователь туннеля) и, по кнопке, `no-password.sh` (вход только по
ключу). Это общие файлы для всех версий приложения; `build.sh` вкладывает их в `.app`. Повторный запуск
безопасен; ошибка — строка `PT-ERROR: …`.

Первый запуск сам открывает настройки. Вкладка **«Автоматически»**:

1. Пользователь вписывает адрес. Через секунду приложение **в фоне** пробует войти админом (`root`) по ключу:
   ключи из `~/.ssh`, агент и ключ входа, который приложение создало раньше. Если ключ добавили при создании
   сервера, логин и пароль не спрашиваются. «Настроить сервер» без адреса подсвечивает поле адреса.
2. Только если ни один ключ не подошёл, появляются логин и пароль и галочка «Создать ключ для входа и добавить
   его на сервер» (включена). Пароль передаётся ssh через временный `SSH_ASKPASS` (нужен OpenSSH ≥ 8.4 —
   в macOS 13 он 9.0) и нигде не сохраняется.
3. «Настроить сервер»: ключ туннеля → вход (сначала снова по ключу) → `setup.sh` → ключ входа админа
   (`~/Library/Application Support/Proxy Tunnel/admin_ed25519`) → настройки сохраняются → выход через туннель.
   Затем «Включить туннель для Claude» и перезапуск Claude.

Блок **«Доступ к серверу»** после настройки: «Проверить соединение» — три входа по ключу подряд, включён ли
вход по паролю (`sshd -T`), выход через туннель. «Выключить вход по паролю» доступна, только когда три входа
по ключу прошли; после скрипта приложение снова входит по ключу и проверяет, что сервер больше не предлагает
пароль. Если ключа нет — «Создать ключ и добавить» по паролю.

«Забыть ключ сервера…» в «Дополнительно» — только после подтверждения: нужно, когда сервер переустановили.

Вкладка **«Вручную»** — команда в буфер обмена для консоли хостинга: когда приложению на сервер не попасть или
хостинг требует сменить пароль при первом входе.

Код — `menubar/Setup.swift` (ssh от имени админа), `Model.swift` (`probeAccess`, `setupServer`,
`checkConnection`, `disablePasswordLogin`); что ответил сервер — в журнале.

## Скрипты

Работают с настройками приложения, без него не нужны:

- `check.sh` — те же проверки из терминала; последняя строка «МОЖНО»/«НЕЛЬЗЯ», код выхода 0 — можно;
- `mode.sh tunnel | vpn` — тот же переключатель режима; без аргумента показывает текущий.
